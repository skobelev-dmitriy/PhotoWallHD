# Автовыкатка на проектор

Цель: после того как ассистент запушил коммит в GitHub, ваш компьютер сам забирает его, собирает и ставит на проектор по ADB. Больше не нужно
каждый раз просить локальный Claude Code «забери и выкати».

## Быстрый старт (Windows)

Один раз:
1. На проекторе включена отладка по сети; узнайте его адрес (Настройки → Сеть). Закрепите за ним постоянный IP в роутере.
2. Проверьте вручную: `adb connect 192.168.1.9:5555`, затем `adb devices` (проектор должен быть в статусе `device`; на проекторе подтвердите запрос отладки).
3. Проверьте одну выкатку: `tools\deploy\deploy.cmd -Device 192.168.1.9:5555`.

Дальше постоянно: откройте вкладку Terminal в Android Studio и запустите

```
tools\deploy\watch.cmd -Device 192.168.1.9:5555
```

Окно оставьте открытым. Каждые 20 секунд скрипт спрашивает у GitHub, не появился ли новый коммит в ветке `ccr-9574af34-ocqfdd` (запрос `git ls-remote`, почти бесплатный).
Увидел новый: `git fetch` + fast-forward, `gradlew installDebug` (Gradle сам ставит APK через adb), выдаёт разрешения (запись звука, «поверх окон») и запускает приложение.
По успеху звучит сигнал. Если сборка упала, повторно не пытается, пока не придёт следующий коммит; если проектор недоступен (выключен), пробует снова каждую минуту.
Остановка: `Ctrl+C`.

В конце выкатки скрипт печатает «На проекторе: версия …, сборка …» (из `dumpsys package`) и сравнивает её с SHA коммита; посмотреть вручную в любой момент:
`adb shell dumpsys package app.photowall | findstr version`. Про схему версий: [docs/VERSIONING.md](../../docs/VERSIONING.md).

Параметры: `-Branch имя`, `-Interval секунд`, у `deploy.cmd` ещё `-NoPull` (не трогать git), `-Release` (собрать релизную сборку).
Скрипт не затирает вашу работу: если в рабочей папке есть незакоммиченные изменения или ветку нельзя обновить fast-forward, он остановится с понятным сообщением.

## Почему именно так (и почему не вебхук)

| Вариант | Вывод |
|---|---|
| **Опрос GitHub с вашего компьютера (этот)** | Просто и безопасно: ничего не открывается наружу, работает за домашним роутером, не зависит от очереди GitHub Actions. Задержка до 20 секунд плюс время сборки. |
| Вебхук GitHub | Нужен публичный адрес на вашем компьютере (туннель вроде ngrok/Cloudflare): лишняя дыра наружу ради выигрыша в 20 секунд. Не рекомендую. |
| Self-hosted runner GitHub Actions на вашем ПК | Рабочий официальный способ (push запускает сборку у вас), но репозиторий **публичный**: чужие pull request могут запустить код на вашем компьютере. Допустимо только для приватного репозитория или с жёстким ограничением на `push` в нужную ветку. Не включал. |
| Скачивать APK из Actions | Не нужна локальная сборка, но зависит от GitHub (раньше сборки стояли в очереди по 15–20 минут) и требует `gh`. Можно добавить, если локальная сборка медленная. |
| Просить локальный Claude Code циклом (`/loop`) | Работает, но тратит токены на каждый опрос. Скрипт делает то же без ИИ; Claude нужен, когда что-то сломалось. |

## Важно

- Скрипты написаны для Windows PowerShell 5.1 и **в облачной среде не запускались** (там нет PowerShell). Если что-то не работает, попросите локальный Claude Code:
  «Запусти `tools\deploy\deploy.cmd -Device <ip>:5555`, исправь скрипт, если он падает, затем запусти `watch.cmd`». Это быстрая проверка на вашей машине.
- Выкатывается всё, что окажется в ветке: пока пушу я, это нормально; не давайте право записи в репозиторий посторонним.
- Сменились только веб-ресурсы (`index.html`)? Приложение всё равно пересобирается: страница лежит внутри APK. Если это станет мешать, можно добавить режим разработчика, подхватывающий страницу с карты памяти без пересборки.
