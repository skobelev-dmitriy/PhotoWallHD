# Архитектура PhotoWall HD

Нативное Android-приложение на Kotlin, **без внешних зависимостей** (только Android SDK). minSdk 23, targetSdk 34.
Весь пользовательский интерфейс на проекторе построен кодом (без XML-разметки), чтобы им можно было управлять пультом.

## Компоненты (`app/src/main/java/app/photowall/`)

| Файл | Роль |
|---|---|
| `MainActivity` | Главный экран: адрес для загрузки, число фото, кнопки. Автозапуск показа с отсчётом 5 с (один раз за запуск процесса). |
| `SlideshowActivity` | Полноэкранный показ. Держит экран включённым, обрабатывает кнопки пульта. |
| `SlideshowView` | Сам показ: два `ImageView` с переходами, Ken Burns, часы, затемнение, ночное расписание, предзагрузка следующего кадра. Используется и в Activity, и в заставке. |
| `PhotoDream` | `DreamService`: показ как системная заставка. |
| `SettingsActivity` | Настройки с пульта: каждая строка — кнопка, меняющая значение по кругу. |
| `ServerService` | Foreground-сервис: держит веб-сервер, запускает показ при загрузке и по расписанию. |
| `BootReceiver` | Запускает сервис при включении устройства и после обновления приложения. |
| `HttpServer` | Свой маленький HTTP/1.1-сервер на `ServerSocket`: потоковая загрузка больших файлов, без зависимостей. |
| `WebApi` | Маршруты веб-интерфейса (см. [API.md](API.md)). |
| `PhotoStore` | Папка с фото и подпапками (один уровень), загрузка, перемещение, миниатюры (кэш). |
| `Playlists` | Плейлисты (папки + отдельные фото + окно времени), выбор активного плейлиста по запросу или расписанию, `playlists.json`. |
| `BitmapLoader` | Декодирование под размер экрана, EXIF-поворот, ограничение 4096 px по большей стороне. |
| `DiscoActivity`, `DiscoView` | Режим дискотеки: полноэкранный Canvas, смена эффектов, подсказки. См. [DISCO.md](DISCO.md). |
| `AudioFeed` | Звук → числа: микрофон / системный звук / демо, FFT, полосы, бит. |
| `Visuals` | Эффекты дискотеки (спектр, круг, кольца, осциллограф, цветомузыка, фейерверк, звёзды, холмы). |
| `Live`, `LiveMath`, `LiveImageView` | «Живые фото»: рецепты (маски + эффекты) рядом с фото, клиент сервиса распознавания, формулы эффектов, отрисовка сеткой. См. [LIVE-PHOTOS.md](LIVE-PHOTOS.md). |
| `Prefs` | Настройки в `SharedPreferences`, JSON-представление для веба, логика расписания. |
| `Util` | `tr()` (рус/англ), определение IP, `Remote` (управление показом из веба), стили кнопок. |
| `assets/web/index.html` | Страница управления для телефона/компьютера (один файл, без сборки). |

## Как это работает

1. При запуске приложения стартует `ServerService` (foreground, тип `dataSync`) и поднимает `HttpServer` на порту **8080**
   (если занят — пробует 8081…8090). Реальный порт лежит в `ServerService.port`.
2. Браузер открывает `http://<ip-проектора>:8080`, страница работает с API: загружает фото, меняет настройки,
   шлёт команды показу.
3. Фото хранятся в `Android/data/app.photowall/files/photos/`. Загрузка — это `POST` с «сырым» телом файла
   (не multipart), поэтому большие файлы идут потоком на диск, а не в память.
4. `SlideshowView` каждый раз перечитывает настройки из `Prefs`, поэтому изменения из веба действуют со следующего слайда.
5. Предпросмотр: для показа веб-страница берёт миниатюру текущего фото (`/api/now` + `/api/thumb`). Для дискотеки `/api/frame`
   просит UI-поток один раз отрисовать текущий эффект в маленький `Bitmap` с `dt = 0` (анимация на экране при этом не сдвигается)
   и отдаёт JPEG; страница опрашивает его ~2 раза в секунду.
6. Команды из веба (`next`, `prev`, `pause`…) попадают в показ через `Remote.view` на главном потоке.

## Память и 4K

- Фото декодируются с `inSampleSize` (степень двойки) так, чтобы результат был не меньше экрана; на 4K-экране
  держатся кадры до 3840×2160. Дополнительно кадр ограничивается 4096 px, иначе часть GPU не загрузит текстуру.
- В памяти одновременно: показываемый кадр, уходящий кадр (во время перехода) и предзагруженный следующий.
  Предзагрузка стартует только после окончания перехода. В манифесте включён `largeHeap`.

## Расписание

`Prefs.inActiveWindow()` понимает и обычные окна (09:00–18:00), и через полночь (18:00–02:00).
Вне окна `SlideshowView` закрывает экран чёрным. Сам проектор приложение не выключает.
`ServerService` раз в 20 с проверяет переход «ночь → день» и при включённом автозапуске поднимает показ.
Запуск из фона на Android 10+ требует разрешения «Показ поверх других окон».

## Сборка и подпись

Сборка: GitHub Actions (`.github/workflows/build.yml`), артефакт `PhotoWallHD-apk`; по тегу `v*` — ещё и GitHub Release.
Подпись фиксированным ключом `app/debug.keystore` (пароль `android`), поэтому обновления ставятся поверх. Ключ публичный,
защиты от подделки подпись не даёт; для публикации в магазине нужен собственный ключ.
`versionCode` берётся из номера запуска CI (`GITHUB_RUN_NUMBER`).
