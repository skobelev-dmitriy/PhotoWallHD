# Промпт для запуска отдельного проекта «Параллакс»

Скопируйте текст ниже в Claude Code на вашем компьютере (в пустой папке нового проекта, например `D:\!Projects\photowall-parallax`; Docker должен быть установлен и запущен).

---

Ты начинаешь новый проект **photowall-parallax**: локальный Docker-сервис, который режет фотографии на слои с достроенным фоном для эффекта параллакса.
Контекст и дизайн уже написаны в соседнем проекте PhotoWall HD (папка `D:\!Projects\PhotoWallHD`, GitHub `skobelev-dmitriy/PhotoWallHD`, ветка `ccr-9574af34-ocqfdd`).

**Сначала прочитай, ничего не переписывая:**
1. `D:\!Projects\PhotoWallHD\docs\PARALLAX-DESIGN.md` — главный документ: конвейер, формулы, формат результата, API/интерфейс, лицензии, критерии приёмки, что не проверено.
2. `D:\!Projects\PhotoWallHD\docs\EFFECT-SPEC.md` и `LIVE-PHOTOS.md` — соседние «живые» эффекты (для контекста и стиля).
3. `D:\!Projects\PhotoWallHD\vision\` — готовые куски: `app/depth.py`, `app/inpaint.py`, `app/backends.py`, `app/classes.py`, `tests/` (синтетическая сцена `tests/synth.py`), `Dockerfile`, `docker-compose.yml`.
4. `D:\!Projects\PhotoWallHD\docs\STATUS.md` и `CLAUDE.md` — стиль работы владельца и что проверено.

**Что сделать (по порядку; после каждого шага запускай тесты и коммить):**
1. Создай проект в текущей папке: `git init`, структура как в `vision/` (FastAPI, Python 3.13, `app/`, `tests/`, `Dockerfile`, `docker-compose.yml`, `README.md`, `CLAUDE.md` с картой проекта и правилами). Скопируй нужные куски из `vision/app` (depth, inpaint, backends, classes) и тесты.
2. Реализуй конвейер из дизайна: нарезка на слои (k-means по глубине, очистка, привязка к объектам из сегментации), построение слоёв с полосой «за ближним» и достройкой, рецепт `recipe.json`, `bundle.zip`. Сначала с синтетической сценой и «истинной глубиной» (тесты на инвариант нулевого смещения и отсутствие дыр), потом с реальными моделями.
3. Библиотека фото на диске (том `./data:/data`) и API из дизайна.
4. Страница `/`: библиотека (загрузка нескольких фото) и вкладка «Параллакс» с живым предпросмотром на `<canvas>`, панелью слоёв и ползунками (формулы из дизайна, без перерасчёта на сервере при движении ползунков).
5. Подключи **настоящие модели** в Docker: Depth Anything V2 Small (`depth-anything/Depth-Anything-V2-Small-hf`, на CPU), проверь, в какую сторону у неё карта глубины (если ближнее тёмное — исправь ориентацию и сохрани переключатель «инвертировать»). Лицензии проверь по официальным репозиториям и карточкам моделей (в первую очередь SegFormer: возможно, некоммерческая; при необходимости замени).
6. Опционально LaMa для достройки (`INPAINT_BACKEND=lama`), сравни с push-pull на реальных фото.
7. Прогони 10–20 реальных фото разных жанров, которые попросишь у владельца (или возьми из его папки фото, если дал доступ), посмотри результат глазами (скриншоты страницы через Playwright), подбери значения по умолчанию, запиши в `README.md`, каким фото параллакс не идёт, и добавь автоотбраковку.

**Правила:**
- Говори по-русски, честно разделяй «проверено» и «не проверено» (в прошлых сессиях не было доступа к весам моделей и к Docker: теперь он есть, используй). Не выдумывай результаты.
- Владелец иногда работает урывками и просит «делай сам»: принимай разумные решения, записывай их и вопросы в `docs/STATUS.md` проекта, не блокируйся.
- Тесты пиши до или вместе с кодом; веб-страницу проверяй Playwright-тестами. Скорость и качество измеряй и записывай числами.
- Не копируй в репозиторий чужие веса и датасеты; фото владельца в git не коммить (папка `data/` в `.gitignore`).
- Формат результата (`recipe.json`, имена слоёв, формулы) должен остаться совместимым с `PARALLAX-DESIGN.md`, потому что его потом будет рисовать Android-приложение PhotoWall HD (Kotlin). Если меняешь формат или формулы, обнови и документ дизайна, и тесты.
- В конце работы напиши владельцу короткий итог: что сделано, что проверено на реальных моделях, что не получилось, какие значения по умолчанию выбраны, и что нужно сделать в приложении PhotoWall HD (рисование слоёв), с ссылкой на раздел «Интеграция» дизайна.
