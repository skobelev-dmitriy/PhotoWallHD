# Параллакс по слоям: дизайн (для отдельного проекта)

Цель: из обычного фото получить **стопку слоёв** (дальний фон, средний план, ближний план…) с прозрачностью и достроенным фоном за ближними
слоями, чтобы при медленном «плавании камеры» ближнее смещалось сильнее дальнего. Картина остаётся статичной, но «живой» (объём).
Работает вместе с «живыми» эффектами воды/листвы (см. [LIVE-PHOTOS.md](LIVE-PHOTOS.md)): это отдельный, независимый вид оживления.

Контекст: идея обсуждалась как «вариант B» (слои + достройка фона) из ответа про параллакс. Предварительные куски кода уже в `vision/app/`
(`depth.py`, `inpaint.py`, тесты `vision/tests/test_parallax_seed.py`).

## Что проверено, а что нет

- Проверено (облачная среда, без GPU и без весов): достройка дыры методом push-pull (ошибка около 2 из 255 на гладком фоне), запасная «глубина без модели»
  (грубая, только для проверки конвейера), откат на неё, если модель не загрузилась.
- **Не проверено ни разу:** Depth Anything V2 (нет доступа к HuggingFace), ориентация его карты глубины (ближе = светлее?), LaMa, SegFormer, Docker, скорость на
  вашем компьютере, внешний вид результата на реальных фото. Всё это — задача нового проекта.

## Конвейер

Рабочее разрешение: длинная сторона до 1280 px (слои для проектора потом масштабируются под экран).

1. **Глубина.** Карта 0..1, где 1 — ближе всего. Бэкенды (`app/depth.py`): `depth_anything` (Depth Anything V2 Small через `transformers` `pipeline("depth-estimation")`,
   модель `depth-anything/Depth-Anything-V2-Small-hf`, на CPU порядка секунд) и `heuristic` (запасной). Переключатель «инвертировать глубину» обязателен.
   Нормализация по 2–98 процентилям (`robust_normalize`).
2. **Нарезка на K слоёв (2–6, по умолчанию 4).** Одномерная k-means по гистограмме глубины даёт пороги; метки `0..K-1` (0 — самый дальний).
   Очистка: медианный фильтр, удаление мелких островков. Необязательно «привязка к объектам»: компоненты классов person/animal/foliage из сегментации
   (SegFormer, см. `app/backends.py`, `app/classes.py`) целиком получают метку большинства пикселей, чтобы человек не разваливался на два слоя.
   Крупные классы (небо, вода, земля) не привязывать: у них глубина действительно меняется.
3. **Слои с достройкой.** Для слоя `i` (от дальнего к ближнему):
   - `own = labels == i`, `nearer = labels > i`;
   - `M = ceil(1.3 · A · W · (d_max − d_i)) + 2` px — наибольший сдвиг, на который ближние слои могут открыть этот слой;
   - `band = nearer ∧ (расстояние до own ≤ M)` — полоса «за ближним», которую нужно достроить;
   - RGB слоя = исходник там, где `labels ≤ i` (известно), в остальном достройка (`PushPullInpainter`, опционально LaMa, `INPAINT_BACKEND=lama`);
     RGB заполнен **везде** (чтобы билинейная выборка не давала тёмных каёмок на краю альфы);
   - альфа: `own ∨ band`; у слоя 0 альфа = 1 везде (фон полный). Мягкий край: размытие альфы на `feather` px только снаружи от «внутренности» `own`.
   **Инвариант:** при нулевом смещении камеры композиция всех слоёв совпадает с исходником (допуск: средняя абсолютная ошибка < 2 из 255).
4. **Рецепт и файлы** (ниже). **Предпросмотр:** анимированный GIF и живой предпросмотр в браузере.

## Камера и формулы (спецификация «parallax v1»)

`d_i` — средняя глубина слоя, `focus ∈ [0,1]` — глубина, которая не смещается (по умолчанию 0.5), `A` — амплитуда (доля ширины, по умолчанию 0.012),
`f` — скорость (циклов/с, по умолчанию 0.08), `t` — время, `W`, `H` — размер слоя, `norm = max(focus, 1 − focus)`.

```
cx = sin(TAU·f·t)                 cy = 0.35·sin(TAU·2·f·t + 1.0)         # единичный путь камеры (петля)
shift_i = A · (d_i − focus) / norm                                     # в долях ширины
dx_i = shift_i · cx ,   dy_i = shift_i · cy                            # смещение слоя
zoom = 1 + 2.2·A                                                       # общее увеличение, чтобы не были видны края
```

Слой рисуется со сдвигом `(dx_i·W, dy_i·W)` пикселей и увеличением `zoom` вокруг центра; композиция «снизу вверх» (от `i = 0` к ближнему), обычное альфа-смешивание.
Время входит только с целыми множителями `f` (петля без шва, как у «живых» эффектов). Реализация Python (`render`) и Kotlin (в приложении) должны совпадать;
для сверки создать `reference_parallax.json` по образцу `vision/tests/gen_reference.py`.

## Формат результата (на каждое фото)

```
<data>/photos/<id>/original.jpg  thumb.jpg  meta.json
<data>/photos/<id>/parallax/recipe.json  depth.png  layer-0.png … layer-{K-1}.png  preview.gif
```

`recipe.json`:

```json
{
  "version": 1, "type": "parallax",
  "image": {"width": 4000, "height": 3000}, "work": {"width": 1280, "height": 960},
  "params": {"layers": 4, "amplitude": 0.012, "focus": 0.5, "speed": 0.08, "feather": 1.0},
  "depth_backend": "depth_anything", "inpaint_backend": "pushpull",
  "layers": [
    {"id": "L0", "png": "layer-0.png", "depth": 0.12, "coverage": 1.0},
    {"id": "L1", "png": "layer-1.png", "depth": 0.41, "coverage": 0.36}
  ]
}
```

PNG слоёв — RGBA, длинная сторона до 1280 px (на проекторе слои потом растягиваются под экран; память: K слоёв × 1280×960×4 ≈ 5 МБ каждый).

## Сервис и интерфейс (в новом проекте)

FastAPI + Docker, данные в томе `./data:/data` (фото остаются между запусками), страница `/` с вкладками:

- **Библиотека:** загрузка нескольких фото (кнопка и перетаскивание), сетка миниатюр, выбор, удаление.
- **Параллакс** для выбранного фото: ползунок «слоёв» (2–6), «инвертировать глубину», «рассчитать» (серверная часть); дальше **без перерасчёта в реальном времени**:
  амплитуда, фокус, скорость, режим «авто / мышь». Живой предпросмотр на `<canvas>` (`requestAnimationFrame`, слои — PNG, формулы выше). Панель слоёв «как в Photoshop»:
  включить/выключить каждый слой, посмотреть карту глубины, посмотреть отдельный слой. Кнопки: скачать рецепт со слоями (`bundle.zip`), GIF-превью.
- API: `POST/GET/DELETE /api/library`, `POST /api/parallax/{id}`, `GET /api/parallax/{id}/recipe|depth.png|layer/{i}.png|preview.gif|bundle.zip`, `GET /api/config`.
  Тяжёлые вычисления в пуле потоков; идентификатор `[0-9a-f]{12}`; лимит загрузки 60 МБ; имена файлов фиксированы (никаких путей от клиента).

## Модели и лицензии (**проверить до коммерческого использования**)

- Depth Anything V2 **Small** — по вторичным источникам Apache-2.0 (Base/Large — некоммерческие); MiDaS и ZoeDepth — MIT. Сверить файлы лицензий в официальных репозиториях.
- SegFormer (`nvidia/segformer-b2-finetuned-ade-512-512`, используется в `vision/` для сегментации): на карточке модели лицензия помечена как «other» —
  **возможно, некоммерческая; проверить**, при необходимости заменить моделью с разрешающей лицензией.
- LaMa (достройка) — проверить лицензию весов и обёртки `simple-lama-inpainting`.

## Критерии приёмки

- Юнит-тесты (по образцу `vision/tests/`): k-means по плато глубины даёт истинные метки; push-pull; **инвариант нулевого смещения**; при сдвиге нет прозрачных дыр;
  пиксели, открытые за ближним слоем, берутся из фона, а не чёрные; API: загрузка → расчёт → слои → удаление.
- Playwright: загрузка нескольких фото, расчёт, живой `<canvas>` не пустой и меняется во времени, переключатели слоёв работают.
- На вашем компьютере в Docker: 10–20 реальных фото разных жанров (пейзаж, портрет, интерьер, город). Для каждого оценить глазами: не рвётся ли человек, нет ли «резиновых» краёв,
  видны ли швы; подобрать значения по умолчанию (число слоёв, амплитуда, перо). Записать, какие фото параллакс **не украшает** (стекло, зеркала, плоские сцены),
  и придумать автоотбраковку (например, разброс глубины ниже порога → «параллакс не нужен»).
- Скорость (цели, не измерения): расчёт ≤ 10–15 с на фото 1280 px на CPU, предпросмотр 30 кадров/с в браузере.

## Интеграция с PhotoWall (после готовности)

1. `VisionClient.parallax(...)` (по образцу `analyze` в `Live.kt`): проектор отправляет фото в сервис и сохраняет `recipe.json` и слои рядом с фото
   (`.live/<ключ>/parallax/`), как сейчас рецепт «живых» эффектов.
2. Рисование в `SlideshowView`: слои PNG ≤ размера экрана, `Canvas.drawBitmap` со своей матрицей на слой (дёшево, без сетки); формулы из этого документа,
   проверка чисел между Python и Kotlin. Параллакс и эффекты воды/листвы складываются (разные проходы).
3. Веб-страница проектора: в редакторе «Оживить» вкладка «Параллакс» со слоями и ползунками, переключатель «оригинал / с эффектами».
4. MCP: инструмент `animate_photo` получает режим `parallax`.
