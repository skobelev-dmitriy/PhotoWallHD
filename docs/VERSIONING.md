# Версионирование

Чтобы всегда было видно, какую версию сделал ассистент и какая стоит на устройстве.

## Схема

- **`versionBase`** в `version.properties` — читаемая версия `MAJOR.MINOR.PATCH` (сейчас 1.4.0). Её поднимает тот, кто пушит изменения:
  минорную (1.4 → 1.5) за новую функцию, патч (1.4.0 → 1.4.1) за исправление, веб-страницу и инструменты. Описание — в `CHANGELOG.md`.
- **`versionName`** на устройстве: `1.4.0-abc1234` — версия + короткий SHA коммита, из которого собрано; `-dirty`, если у отслеживаемых файлов
  были незакоммиченные изменения (сборка из Android Studio с правками). С параметром `-PreleaseBuild=true` — чистая `1.4.0` (для публикации).
- **`versionCode`** = `100 + число коммитов в ветке` (`git rev-list --count HEAD`): растёт с каждым коммитом, поэтому новая сборка всегда ставится поверх старой.
  (Раньше при локальной сборке было 1, а у сборок из GitHub Actions — номер запуска; новая схема выше обеих.)
  Без git (архив без истории) получится 100 и `-nogit`.

## Где это видно

| Где | Что |
|---|---|
| Проектор, главный экран | «v1.4.0-abc1234 · сборка 115» внизу |
| Веб-страница | значок рядом со статусом: `v1.4.0-abc1234 · #115` |
| API | `GET /api/ping` и `GET /api/state`: `version`, `versionCode` |
| GitHub Actions | `PhotoWallHD-1.4.0-abc1234.apk` |
| Компьютер | `./gradlew printVersion` печатает версию, которая получится при сборке; `adb shell dumpsys package app.photowall \| findstr version` — что стоит на проекторе |
| Автовыкатка | в конце печатает «На проекторе: версия …, сборка …» и предупреждает, если SHA не совпал |

Как сверить: SHA в версии на проекторе совпадает с `git rev-parse --short HEAD` вашей ветки, значит, стоит именно последний коммит.

## Правило для ассистента

При каждом пуше, меняющем приложение, веб-страницу или инструменты: поднять `versionBase`, добавить запись в `CHANGELOG.md`, а в ответе назвать версию и номер сборки
(`100 + git rev-list --count HEAD` после коммита; SHA — `git rev-parse --short HEAD`).
