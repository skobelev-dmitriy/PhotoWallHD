# «Живые» фото

Фото остаётся статичным, но в нескольких областях пиксели чуть смещаются: вода покачивается, листва шевелится, облака «дышат»,
человек едва заметно «дышит». Поверх этого работает прежнее медленное приближение (Ken Burns).

## Как это устроено

```
 браузер ──(фото на проектор)──▶ проектор ──(уменьшенное фото, JPEG 1024 px)──▶ сервис распознавания (Docker, ваш ноутбук/VPS)
                                    ◀──(рецепт: маски + эффекты + параметры + превью)──┘
 проектор хранит рецепт рядом с фото и рисует движение при показе
```

1. **Сервис распознавания** ([`vision/`](../vision/README.md)) находит области (вода, листва/пальмы, небо, человек, ткань/флаг),
   строит маски с мягким краем и рекомендует эффект с параметрами. Модель: SegFormer (ADE20K) или запасной «классический» режим без модели.
2. **Проектор** ходит к сервису сам: адрес задаётся в настройках («Адрес сервиса распознавания», `visionUrl`).
   Проектор должен «достучаться» до сервиса по сети: тот же Wi-Fi или VPS с открытым портом (в интернет без защиты не выставляйте).
3. **Рецепт** хранится в `photos/.live/<размер>-<время>/` (`recipe.json`, маски PNG, `preview.gif`, `overlay.png`); он не теряется при
   перемещении фото или переименовании папки.
4. **Показ:** приложение рисует фото через сетку (~128 узлов по ширине, `Canvas.drawBitmapMesh`): узлы двигаются по формулам из
   [EFFECT-SPEC.md](EFFECT-SPEC.md). Это дёшево для слабого процессора, а края кадра не двигаются. При ошибке рецепта показ не останавливается.

## Как пользоваться

1. Поднимите сервис: `cd vision && docker compose up --build` (подробности в [vision/README.md](../vision/README.md)).
   Проверьте в браузере `http://<адрес-ноутбука>:8090`.
2. На веб-странице проектора: Настройки → «Адрес сервиса распознавания» → `http://<адрес-ноутбука>:8090`.
3. Выберите **одно** фото → «✨ Оживить» → «Найти области и предложить эффекты». Появятся: что «увидела» модель (цветные области),
   анимированный предпросмотр (движение ×3) и список областей. Для каждой можно включить/выключить эффект и задать силу (0…300 %), затем «Сохранить».
4. Фото с анимацией помечены ✨. Глобально: «Показывать лёгкое движение» и «Сила движения» (на веб-странице и в настройках на пульте).
5. Через MCP: инструмент `animate_photo` (analyze / show / update / remove).

## Что проверено и что нет

- Проверено: формулы (Python и Kotlin дают одинаковые числа на 75 контрольных точках), выделение областей «классическим» режимом
  на синтетическом пейзаже и на реальном снимке, API сервиса, веб-интерфейс (в браузере на поддельном проекторе), компиляция приложения.
- **Не проверено:** Docker-образ (в среде разработки не было Docker-демона), SegFormer с реальными весами (не было доступа к HuggingFace),
  отрисовка на реальном проекторе (как выглядит движение, нагрузка на процессор, плавность на 4K, поддержка `drawBitmapMesh` на Wanbo).
- «Классический» режим грубый: на тёмных небесах и ночных кадрах ошибается (на реальном снимке с грозовым небом он нашёл небо и луг,
  но не нашёл пруды). Для настоящей работы нужен SegFormer.

## Ограничения и дальнейшие шаги

- Платье и волосы «по ветру» не делаются (нужны отдельные маски деталей или нейросеть-видео), у человека только «дыхание».
- Параметры эффектов сейчас подбираются эвристиками по размеру и положению области; их можно уточнять (в том числе ИИ через OpenRouter).
- Автоанализ при загрузке фото и пакетная обработка папки пока не сделаны: анализ запускается вручную для каждого фото.
- Предпросмотр на веб-странице — это то, что считает сервис (поэтому ×3); на проекторе движение точно такое же по формулам, но в реальном времени.
